# Restaurant SEO and share-preview audit — November 23, 2026

## Issues corrected

- Most routes originally returned the homepage title, homepage canonical, a logo-only image, no H1 and no JSON-LD in the initial response. Only three arcade routes had custom static share metadata.
- The original restaurant JSON-LD contained an unsupported 4.5 rating and 200-review count, an empty email, and an `acceptsReservations: false` assertion despite a party-request form. These fields have been removed.
- The Contact description said lunch was available every day even though published Monday/Tuesday opening time is 4 p.m. The new description agrees with published hours.
- Unknown routes returned HTTP 200 homepage HTML. They now return the rendered 404 page with HTTP 404 and noindex.
- The TV kiosk was blocked in robots while its noindex was only client-rendered. It is now crawlable with both server-rendered noindex metadata and an X-Robots-Tag.

## Implementation

- `client/src/lib/page-metadata.ts` owns route-specific titles, descriptions, canonical paths and share images. `SEO.tsx` renders them for both static output and client navigation.
- `scripts/prerender-og.mjs` renders full React content for 14 routes plus a Christmas homepage variant. Navigation, menu text, hours, footer links and business schema are available without JavaScript. The existing React app takes over after load. Only generated static head tags are removed on startup, preventing duplicate metadata.
- Seven 1200×630 JPEG share cards use existing restaurant photographs and the existing logo. `scripts/social-images.mjs` reproduces them. Cards cover restaurant, menu, patio/experience, events, storefront/contact, careers and Christmas. Original photos remain unchanged. Arcade cards are retained.
- `structured-data.ts` provides Restaurant/BarOrPub, WebSite, WebPage, breadcrumb and menu data. The 109 menu items come from the same source as the visible menu. No external ratings are manufactured or aggregated.
- Eight visitor questions are visible on Contact and represented in matching FAQ markup. This is useful structured information, not a promise of Google FAQ rich-result eligibility.
- The sitemap is generated from known public routes, excluding the kiosk and 404. The last-modified date records this content revision, not every build time. The existing llms.txt now contains useful business facts and page links; it is supplementary, not a ranking requirement.
- The viewport no longer disables user zoom.
- Wadsworth-local day calculations use America/New_York.

## Season and deployment

`shared/season.ts` is used by the client and `netlify/edge-functions/home-season.ts`.
The edge function serves the pre-rendered Christmas homepage during the campaign;
otherwise normal index.html is served. This keeps initial HTML, social metadata
and visible design consistent after January 1, 2027 at midnight Eastern without
a scheduled rebuild. Normal and Christmas variants share the canonical root URL.
The edge function runs only for the homepage; all other pages remain static.

Deploy `dist/public`, the existing `netlify/functions`, and the configured edge
function together. Netlify CLI deploy includes the edge function automatically.
